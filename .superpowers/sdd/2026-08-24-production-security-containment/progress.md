## Plan rulings

- Task 1 preserves view output columns except `profiles` credential columns, which the approved security design explicitly removes.
- **HARD DEPLOYMENT DEPENDENCY:** Task 3 must migrate `user-races` token reads and writes away from the public `profiles` view to a service-only credential path or base table before Task 8. Task 8 may not deploy Task 1 alone.
- **HARD DEPLOYMENT DEPENDENCY:** Task 5 must implement OAuth callback state handling and settle the callback's `verify_jwt` configuration before Task 8. Do not change `oauth-callback` in Task 3; all containment tasks deploy together.
- Gateway-generated `401` response-shape compatibility is a Task 7/8 runtime validation item because rejected requests may not reach handler code.
- Tests run after each change set because the user explicitly requested post-change testing.
- Migration filenames are generated by the Supabase CLI and recorded in each task report.
- Live secret creation, deployment, credential rotation, or other security-sensitive production actions require an explicit approval stop in Task 8.
